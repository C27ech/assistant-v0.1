# web_tools —— 联网查资料插件

给助手 AI 用的「联网查资料」工具：**搜索**（多引擎 + 学术自动改道 + 垃圾站过滤）+ **读网页正文**。

## 用法

```bat
cd /d C:\path\to\assistant_v0.1/plugins/web_tools

:: 搜索（--source 可省略，默认 auto 自动路由）
python main.py search "图灵机" --n 5
python main.py search "catastrophic forgetting fine-tuning" --n 5
python main.py search "agent memory drift" --n 5 --source academic

:: 读网页正文（无头浏览器渲染，能拿到 JS 动态内容、也能绕简单反爬）
python main.py fetch "https://baike.baidu.com/item/图灵机" --max 4000
```

返回都是**纯文本**，直接给大模型读。

## 搜索是怎么决策的（auto 模式）

```
查询
 ├─ 命中学术特征词（论文/文献/综述/研究/paper/survey/benchmark/study…）且含拉丁词条
 │     └─→ arXiv + OpenAlex + Crossref（都是英文库，只把拉丁词条传过去）
 ├─ Bing 网页搜索
 │     └─ 结果 ≥50% 是词典站（英文技术查询会被 Bing 退化成「查单词」）→ 丢弃并改走学术库
 └─ 合并 → 按标题/链接去重 → 域名评分 → 排序
```

**域名评分**（`domain_score`）—— **分三档**，避免「百科」跟「一手权威来源」同分：

| 档 | 范围 | 分值 |
|----|------|------|
| **一档** | 一手/权威：arXiv / OpenAlex / DOI / Crossref / nature / ACM / IEEE、官方文档（python.org / MDN / readthedocs）、代码仓库（GitHub / GitLab）、`.gov` / `.edu` | **+4** |
| **二档** | 技术社区/经验：StackOverflow / 知乎 / CSDN / 掘金 / 博客园 / B站 | **+1** |
| **三档** | **百科类**：百度百科 / 搜狗百科 / 萌娘百科 —— 门槛低、校对少、错漏多，**只当线索** | **0**（不加分）|
| 黑名单 | 导航站（hao123/2345/360）、下载站、内容农场（百家号/知道/经验/文库/头条/搜狐号）| **−6** |
| 不可达 | `wikipedia.org` 等本机打不开的站 | **−99**（直接剔除）|
| 可疑模式 | 域名带 4 位以上数字、3 个以上连字符、标题含「导航/大全/下载站」 | −1 ~ −3 |
| 学术来源 | 一手文献额外加权 | **+1** |
| **合计 ≤ −3** | 直接丢弃 | — |

**输出会标注来源可信度**，助手据此把握引用分寸：

```
1. ［社区经验］什么是 图灵机 ？ - 知乎
2. ［社区经验］图灵机 详解-CSDN博客
3. ［社区经验］图灵机 ：计算机世界的理论基石 - 知乎
```

引用百科类结果时，会自动附带这句提醒：

```
（注意：标「百科·可信度低」的是用户可自由编辑的百科站，门槛低、错漏较多，只能当线索。
  人名 / 时间 / 数字 / 结论这类关键事实，请用［文献］或［权威］来源交叉验证……）
```

| 标签 | 含义 |
|------|------|
| ［文献 YYYY］ | 学术库一手论文（最可信）|
| ［权威］ | 官方文档 / 代码仓库 / 政府教育站 |
| ［社区经验］ | 知乎 / CSDN 等（有参考价值但非权威）|
| ［百科·可信度低］ | 可自由编辑的百科站（只能当线索）|

## 实测（6 个场景）

| 查询 | 结果 |
|------|------|
| `图灵机` | 社区经验（知乎/CSDN）优先；含百科结果时自动标注「可信度低」并附交叉验证提示 |
| `python asyncio 教程` | 官方文档（权威）排在 CSDN（社区经验）之前 |
| `catastrophic forgetting fine-tuning language model` | 检出「70% 是词典站」→ arXiv **5 篇靶心论文**（带摘要）|
| `AI Agent 记忆 人格 漂移 研究` | arXiv 4 篇（AI Agent 架构综述、多智能体共谋机制、agentic AI 安全综述）|
| `深度学习 论文` | 正确**不**硬走英文库 → GitHub 精读仓库 / 知乎 / CSDN |
| `--source academic` + `memory drift LLM agent` | Memory-Induced Tool-Drift / CAPTURE / Agent Drift（正是本项目关心的题）|

## 为什么这样实现（参考豆包 / 元宝 / Cline 的做法）

| | 它们的做法 | 本插件 |
|---|-----------|--------|
| 搜索 | 自建搜索后端，模型只调一个 `web_search` | Bing + 三个学术库，结果打分过滤 |
| 读网页 | **服务端无头浏览器渲染 + 正文提取** | **本地 Playwright 渲染**（自带 Chromium，失败回退系统 Edge）|

**裸 `requests` 抓网页对现代站点基本没用**（实测）：

| 站点 | 裸 HTTP | 浏览器渲染 |
|------|---------|-----------|
| 萌娘百科 | ❌ 只拿到 74 字（JS 渲染）| ✅ 7223 字 |
| 百度百科 | ❌ 403「百度安全验证」| ✅ 10073 字 |
| CSDN | ✅ 6980 字 | ✅ |

## 性能须知（实测）

**每次插件调用 = 一次子进程 + 一次网络/浏览器往返**，而每调一次插件，助手还要多跑一整轮「带完整上下文的模型回合」。所以插件调得越多，回复越慢。

| 操作 | 实测耗时 |
|------|---------|
| 普通回复（不用插件）| 10~25 秒 |
| `fetch_page` 成功一次 | 4.4~6.8 秒 |
| `web_search`（只搜网页）| 1.0 秒 |
| `web_search`（走学术库）| 5.9 秒 |
| **`fetch_page` 抓维基百科（失败）** | **~70 秒**（浏览器 45s 超时 + HTTP 25s 超时）|

### 结论与对策

- ❌ **上下文大小几乎不影响速度**：实测 0K / 10K / 40K / 80K 字的输入，同一问题的耗时都是 0.5~1.3 秒。
  （所以「记忆检索 30 条」不是慢的原因，不用调小。）
- ✅ **真正的耗时来自两处**：① 插件调用次数（尤其抓网页）；② 模型「思考 + 写长回复」的长度
  （实测：短回答 1 秒；max_tokens=8000 且思考 5599 字时 26 秒）。
- 🔧 **本插件已做的优化**：
  1. `wikipedia.org` 全系加入「本机不可达」名单 → **搜索时直接剔除结果，抓取时 0 秒快速失败**（省下每次 70 秒），并提示换来源；
  2. 浏览器超时 45s → **20s**，HTTP 兜底超时 25s → **12s**（最坏 32 秒而不是 70 秒）；
  3. `fetch_page` 的说明里加了纪律：**每次查资料最多抓 3 个页面**、摘要够用就别抓。

## 依赖


- `requests`、`beautifulsoup4`（arXiv 的 XML 用 `html.parser` 解析，**不需要 lxml**）
- `playwright` + Chromium（没装也能跑，会自动回退系统 Edge）

> **国内装 Chromium**（官方 CDN 常不通，用阿里镜像）：
> ```powershell
> $env:PLAYWRIGHT_DOWNLOAD_HOST = 'https://cdn.npmmirror.com/binaries/playwright'
> python -m playwright install chromium
> ```

## 限制

- 需要联网。Bing 对中文长尾词分词偶尔很糟（实测会把专有名词拆成更短的词）→ 查询尽量用专有名词。
- 登录墙 / 复杂验证码 / 纯视频页抓不到（会提示「换一个来源」）。
- 学术库都是英文库；**纯中文查询不会硬走它们**（想强制用 `--source academic`），所以中文论文还得靠网页搜索。
- 正文会截断（`--max`，默认 4000 字），避免超出模型上下文。

## 2. 关键方法：先判定"游戏是否在等输入"，再探测

盲按按键是没用的 —— 过场动画/影片期间游戏**不接受输入**，任何像素差都只是动画。
所以本节点补了一个基础原语：

> **`advance_until_dialogue`**：反复按 ENTER，直到**画面漂移 ≈ 0**（判据＝两张相隔 1.2s 的截图差异 < 1%）。
> 实测：初始漂移 45.55% → 5 次推进后 **0.00%** ⇒ 游戏进入等待输入状态 ✓

只有在"静止态"下，UI 的微小变化才能被可靠探测（手机界面本身是静态的）。

**两个机制（经用户纠正后确认）**
1. **必须开手机的节点 → 按 `Z`（手机触发器）**；这一点与 HELP 里的「手机触发器」一致。

   并不是"用 ENTER 开手机"。
   → 我之前的理解写反了，本节点已按此更正（`phone_act.py` 也改回 **先 Z**、必要时再用 ENTER 推进剧情）。
3. 手机首页底部提示语（「打开收件箱 / 打开发件箱」）**随选中项变化**，可直接当"当前选择"的读数。

| 图片 | 大小 | 结果 |
|---|---|---|
| 游戏全屏 PNG（2400×1350） | 2.1 MB | ✅ 会话早期可读 |
| 400×225 JPEG | ~14 KB | ✅ 一段时间内可读（3 张连着成功） |
| 2 格拼图 JPEG | 6.4 KB | ✅ 成功 1 次 |
| 局部裁剪 JPEG | 7 KB / 3.9 KB | ❌ 被拒 |
| 极小子图 JPEG | **1.5 KB** | ❌ 被拒 |

⇒ **与文件大小无关，是本会话的图像配额/上下文限制**（会话越长越受限）。
处理建议：
1. **需要"看图"的收尾工作，建议新开一个会话继续**（项目目录与三份节点文档已就绪，
   新会话先读 `docs/NODE3_phone.md` §3.4 / §5.2 即可无缝接手）；
2. 或者在旧会话里改为**用户口述屏幕内容**（本次已用这种方式定下了 Z/X 键位 ✓）。

## 5.3 输入法（IME）检查（已并入桥接）

按用户提醒，我加了 `core/ime.py` 并在 `attach` 时自动执行：
* 查窗口线程键盘布局（`GetKeyboardLayout`，LOWORD=LANGID）
* 查 IME 是否打开/是否组字（`ImmGetConversionStatus/ImmGetOpenStatus`）
* 必要时切英文：`WM_INPUTLANGCHANGEREQUEST`(en-US) + `ImmSetConversionStatus`(半角英文) + `ImmSetOpenStatus(False)`

**实测结果**：STEINS;GATE 游戏窗口本来就是 **en-US（langid=0x0409）**，且该窗口 `ime_available=False`
（DirectInput 自绘窗口没有 IME 上下文）⇒ **IME 不是此前的干扰源**。
不过以后换到别的程序/窗口时，这一层能自动兜底。
